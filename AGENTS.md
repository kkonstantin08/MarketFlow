# Инструкции для агентов MarketFlow

1. Перед каждой задачей перечитай этот файл, [состояние проекта](docs/progress.md) и соответствующие документы по [указателю](docs/README.md). В новой сессии восстанови контекст из этих файлов и проверь `git status`.
2. Перед изменением поведения сверься со [спецификацией](docs/specs/mvp.md), [планом](docs/plan.md) и [решениями](docs/decisions.md). Меняй только согласованный объём. При расхождении кода со спецификацией сначала выясни причину. Изменение согласованного поведения отрази в документации.
3. Начинай реализацию только после команды владельца `GO` по согласованному MVP. К интерфейсу переходи после отдельного согласования его объёма, оформления и подхода. После `GO` веди согласованные этапы последовательно и самостоятельно. Уточняй только существенную неопределённость, изменение объёма, внешнее разрешение или выбор интерфейса.
4. Применяй Superpowers и Ponytail, если доступны. Для требований и плана используй `brainstorming` и `writing-plans`, для ошибок — `systematic-debugging`, перед отчётом — `verification-before-completion`. Используй прочитанные инструкции. Выбирай минимальное решение, удовлетворяющее спецификации и тестам.
5. Разрабатывай бизнес-логику по [TDD](docs/testing.md). Увидь ожидаемое падение теста, внеси минимальное исправление, убедись в прохождении, затем упрощай с повторной проверкой. Пиши понятный C# с осмысленными именами. Вводи абстракции только при очевидной необходимости.
6. Проверь состояние Git и чужие изменения перед правками. Сохраняй их, делай небольшие логические коммиты. Публикация репозитория требует отдельного разрешения.
7. Перед завершением сверяй этап с критериями приёмки, запускай применимые сборку и тесты. Сообщай только о фактически выполненных проверках. Обновляй [журнал состояния](docs/progress.md) после значимого этапа. Записывай решения, отклонения, незавершённые задачи, ограничения среды и точку продолжения.
