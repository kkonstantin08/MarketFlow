# Предметная модель

| Сущность | Смысл и связи |
| --- | --- |
| `Product` | Товар с идентификатором, названием и уникальным SKU. Один товар может храниться на нескольких складах. |
| `Warehouse` | Склад с идентификатором и названием. Может хранить много товаров. |
| `Stock` | Текущие количества по паре «товар, склад». Хранит `onHand` и `reserved`. `available` вычисляется как разность. Строка появляется при первой приёмке. |
| `Supply` | Факт приёмки одной позиции на одном складе. Хранит уникальный номер поставки, ссылку на товар и склад, количество и время. Номер позволяет безопасно повторить запрос. |
| `Reservation` | Факт выделения количества одного товара на одном складе. Имеет собственный идентификатор, количество и время. Резерв остаётся активным в течение всего MVP. |
| `StockMovement` | Запись истории по паре «товар, склад». Хранит тип, изменения физических и зарезервированных единиц, время и ссылку на одну поставку или один резерв. |

Количество выражается целыми единицами. Для каждой пары выполняется `0 ≤ reserved ≤ onHand`. Первая приёмка начинает учёт с нуля. Приёмка увеличивает `onHand`, резервирование увеличивает `reserved` и уменьшает доступное количество без изменения физического остатка. При отсутствии строки `Stock` доступных единиц нет.

Каждой успешно зафиксированной приёмке или резерву соответствует одна запись истории. Повтор приёмки с тем же номером и теми же данными возвращает первоначальную операцию. Тот же номер с другими данными — конфликт. Неуспешная операция оставляет все три части неизменными — факт операции, остаток и историю.

Прямых связей товара со складом вне остатков и операций не нужно. Поставщик, заказ и отдельные строки поставки не нужны для однопозиционного сценария. Границы записи определяет транзакция, описанная в [архитектуре](architecture.md).
