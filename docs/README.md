# Документация MarketFlow

Начни с корневого [AGENTS.md](../AGENTS.md), затем прочитай [состояние проекта](progress.md), [спецификацию MVP](specs/mvp.md), [план](plan.md) и [решения](decisions.md). Остальные материалы открывай по задаче.

| Документ | Когда читать и что в нём хранить |
| --- | --- |
| [product.md](product.md) | При уточнении целей и границ продукта. Пользователь, основной сценарий и исключения. |
| [domain.md](domain.md) | При работе с сущностями и складскими правилами. Термины, связи и инварианты. |
| [architecture.md](architecture.md) | При работе с API, БД, транзакциями или запуском. Устройство приложения и алгоритм записи. |
| [specs/mvp.md](specs/mvp.md) | Перед изменением поведения. Контракт API, валидация, ошибки и критерии приёмки. |
| [plan.md](plan.md) | При выборе следующей задачи. Этапы, критерии завершения и проверки. |
| [testing.md](testing.md) | Перед добавлением логики и проверкой этапа. TDD, реальные сценарии PostgreSQL и проверка запуска. |
| [decisions.md](decisions.md) | При изменении проекта. Причины выбора, альтернативы и статус согласования. |
| [progress.md](progress.md) | В начале новой сессии и после каждого значимого этапа. Факты, проверки, препятствия и следующий шаг. |
| [design/research.md](design/research.md) | Перед обсуждением UI. Референсы, лицензии, варианты оформления и реализации. |

Спецификация определяет ожидаемое поведение. Если реализация расходится с ней, установи причину и согласуй изменение требований до правки спецификации. Уточнённый контракт меняй в одном месте, а в план и решения заноси последствия и причину.
