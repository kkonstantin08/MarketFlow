## 2026-11-13 — Выравнивание кнопок операций

В карточках приёмки и резерва формы теперь занимают доступную высоту, а кнопки закреплены у нижнего края. Это выравнивает их по общей линии на широком экране, несмотря на разную высоту поясняющего текста и число полей. Версия CSS обновлена для сброса кэша.

Проверено Chrome через Playwright. Кнопки совпадают по вертикальной позиции и размеру на широком экране. На ширине 390 px карточки остаются адаптивными, горизонтальной прокрутки нет. Compose пересобран.

## 2026-11-13 — Исправления по итогам аудита

**Готово.** Демонстрационная страница очищает результат при смене товара или склада и игнорирует запоздалые ответы. Подтверждение приёмки или резерва остаётся видимым при сбое чтения остатка. HTML проверяет формат номера поставки. API возвращает 400 для чисел в кавычках и нулевых символов в названиях и поиске. OpenAPI описывает реальные ответы операций записи, включая 200 для повтора приёмки и 201 со схемой результата для создания. Порт тестового PostgreSQL привязан к 127.0.0.1.

**Проверки.** Шесть проверок API и OpenAPI воспроизвели прежние ошибки. После правок прошли все 28 тестов на PostgreSQL 17. На отдельном Compose-стенде Chrome через Playwright прошёл сценарий 10/4/6 при ширине 320 px, проверку фокуса через Tab, валидацию номера, задержанный ответ при смене склада и отказ чтения после успешного резерва. Проверены конфигурации Compose и фактическая привязка порта 5433. Удалённый GitHub Actions пока не запускался: Git remote отсутствует.

## 2026-11-13 — Повторный аудит и тестирование MVP

**Проверки.** Проверены исходники API, браузерной страницы, схема и миграции, тесты, Docker Compose и конфигурация CI. Сборка прошла без предупреждений, все 23 теста на PostgreSQL 17 прошли. EF Core подтвердил актуальность миграций. Проверка NuGet не обнаружила известных уязвимостей. На отдельном Compose-стенде с пустой базой Chrome через Playwright прошёл сценарий через кнопки: приёмка 10, повтор без начисления, резерв 4, отказ резерва 7 с сохранением 10/4/6. Проверены клавиатурный фокус через Tab, подписи полей и отсутствие горизонтальной прокрутки при ширине 320 px. На другой паре 24 параллельные приёмки прошли, из 24 параллельных резервов прошли ровно 12, остаток и журнал сошлись. После перезапуска сохранились обе строки остатков и все 39 движений.

**Подтверждённые проблемы.** Запоздалый ответ чтения может показать остаток предыдущего склада. Сбой чтения после успешной записи скрывает подтверждение операции. Браузер игнорирует некорректный шаблон номера поставки. API возвращает 500 для символа NUL в названии или поиске и принимает числовые строки в JSON, хотя контракт требует числа. OpenAPI описывает POST как 200 без схемы ответа, хотя создание возвращает 201 и тело. Тестовый PostgreSQL публикует порт на всех интерфейсах хоста с демонстрационными учётными данными.

**Точка продолжения.** В первую очередь исправить привязку остатка к текущей паре и сохранить подтверждение записи при ошибке чтения. Затем исправить валидацию, описание OpenAPI и привязку порта тестовой базы. Исходники приложения в ходе аудита не менялись. Удалённый GitHub Actions не запускался: Git remote отсутствует.

## 2026-11-13 — Этап 6: демонстрационная страница

**Готово.** Добавлена светлая статическая страница сценария приёмки и резерва, обслуживаемая ASP.NET Core вместе с CSS и JS. Идентификаторы товара и склада вводятся вручную; загрузка не меняет данные. Повтор поставки отправляется один раз по действию пользователя, резерв не повторяется автоматически. После каждого результата страница перечитывает остаток, в том числе после отказа. README описывает сценарий.

**Проверки.** Smoke-тест сначала показал `404` для `/`, после подключения статических файлов проверяет страницу, типы контента, подписи полей, видимый фокус, мобильный media query и маршруты операций. `dotnet test MarketFlow.sln --no-restore` прошёл: 23 теста PostgreSQL. `dotnet build MarketFlow.sln --no-restore` прошёл без предупреждений. Docker Compose пересобран и запущен; статические файлы доступны в контейнере. На новой паре через HTTP проверены приёмка `201`, повтор `200` с тем же ID, резерв и остаток 10/4/6, отказ резерва 7 с `409 insufficient_stock` и неизменными значениями. В браузере просмотрена узкая компоновка; разметка использует подписи `label`, CSS задаёт `:focus-visible` и узкую сетку. Отдельная проверка клавиатурного ввода не выполнялась.

**Следующий шаг.** Этап 7: финальная сверка локальных критериев MVP и фиксация оставшихся ограничений.

## 2026-11-13 — Этап 4: резервирование

**Готово.** Добавлены `Reservation`, миграция и `POST /api/reservations`. Операция проверяет товар и склад, атомарно резервирует только доступное количество условным `UPDATE`, затем в одной транзакции сохраняет факт и движение. История различает `supply` и `reservation`, хранит единственную ссылку на операцию и возвращает соответствующий `operationId`.

**Проверки.** `dotnet test MarketFlow.sln --no-restore` прошёл: 22 интеграционных теста на PostgreSQL 17. Проверены резерв части и всего остатка, недостаток и отсутствие остатка, неизвестные ссылки, некорректное количество, изоляция складов, гонка двух резервов и гонка приёмки с резервом. Ошибка вставки движения откатывает изменение остатка и факт резерва. Сборка без предупреждений, аудит пакетов без уязвимостей, EF Core подтвердил актуальность миграций, Compose-конфигурация валидна, `git diff --check` прошёл.

## 2026-11-13 — Этап 3: остатки, приёмка и история

Запись поставки, остаток и движение фиксируются одной транзакцией. Добавлены `GET /api/stocks` и `GET /api/stock-movements` с фильтрами, сортировкой и пагинацией. **Проверки.** TDD RED подтвердил отсутствие supply-маршрута. `dotnet test MarketFlow.sln --no-restore` прошёл: 16 тестов на PostgreSQL 17.
