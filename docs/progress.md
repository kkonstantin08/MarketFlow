# Состояние проекта

## 2026-11-13 — Этап 3: остатки, приёмка и история

**Готово.** Добавлены `Supply`, составной `Stock`, `StockMovement` и миграция. `POST /api/supplies` нормализует номер, возвращает исходную операцию при точном повторе, сообщает конфликт при повторе с другими данными и использует параметризованные SQL upsert-запросы. Запись поставки, остаток и движение фиксируются одной транзакцией. Добавлены `GET /api/stocks` и `GET /api/stock-movements` с фильтрами, сортировкой и пагинацией. Неожиданные ошибки возвращают общий Problem Details без внутренних подробностей.

**Проверки.** TDD RED подтвердил отсутствие supply-маршрута. `dotnet test MarketFlow.sln --no-restore` прошёл: 16 тестов на PostgreSQL 17. Проверены повтор и конфликт, в том числе параллельные запросы, параллельные первые приёмки разных номеров, физический предел `int.MaxValue`, отсутствие частичной записи при искусственном отказе вставки журнала, успешный повтор после снятия сбоя, фильтрация и страницы чтения. `dotnet build` прошёл без предупреждений, аудит пакетов чистый, EF Core не обнаружил изменений модели после последней миграции, Compose-конфигурация и `git diff --check` прошли.

**Следующий шаг.** Этап 4: атомарное резервирование доступного остатка и движения резерва в общей истории.

## 2026-11-13 — Этап 2: справочники

**Готово.** Добавлены товары и склады, миграция EF Core, создание/чтение, буквальный поиск товара без учёта регистра, нормализация SKU, ограничения длины и ASCII-набора, уникальность SKU, сортировка и пагинация. Ошибки валидации и дубликатов возвращают Problem Details. В Development Swagger доступен, API применяет миграции при старте.

**Проверки.** TDD RED показал отсутствие маршрутов. `dotnet test MarketFlow.sln --no-restore` прошёл: 8 проверок на реальном PostgreSQL 17; каждому сценарию справочников создаётся отдельная временная БД с миграцией. Проверены кириллица, буквальные `%`/`_`, нормализация `box-01`, дубликат SKU, границы полей, повторяющиеся имена складов, страницы, неизвестные ID и Problem Details при ошибочных query-параметрах. `dotnet build MarketFlow.sln --no-restore` прошёл без предупреждений; аудит пакетов не нашёл уязвимостей; `dotnet-ef migrations has-pending-model-changes` подтвердил соответствие миграции модели; `docker compose ... config --quiet` и `git diff --check` прошли.

**Следующий шаг.** Этап 3: остатки, атомарная приёмка, повтор по номеру поставки и журнал движений.

## 2026-11-13 — Этап 1: основа API

**Готово.** Созданы `MarketFlow.sln`, API на .NET 10, xUnit-проект с тестовым хостом и `compose.test.yaml` с PostgreSQL 17. API отвечает `GET /health`, Swagger UI и OpenAPI доступны в Development. SDK 10.0.404 установлен в `~/.dotnet` через официальный скрипт, системная установка не менялась.

**Проверки.** Увиден RED: без маршрутов три smoke-проверки падали (`/health`, Swagger и подключение к отсутствующей тестовой БД). После исправления `docker compose -f compose.test.yaml up -d --wait`, `dotnet test MarketFlow.sln --no-restore` прошёл (3 проверки), `dotnet build MarketFlow.sln --no-restore` прошёл без предупреждений, `dotnet list MarketFlow.sln package --vulnerable --include-transitive` не нашёл уязвимых пакетов. Реальный API на `127.0.0.1:8080` также ответил на `/health`, Swagger UI и JSON спецификации. Docker Compose и PostgreSQL 17. Разработка проверялась только на macOS arm64.

**Изменения.** README содержит команды запуска API и тестовой БД. OpenAPI.NET закреплён на исправленной версии 2.7.5 из-за известной уязвимости в 2.3.0. Superpowers-инструкции в доступном каталоге навыков этой сессии не обнаружены; TDD выполнен по `docs/testing.md`.

**Следующий шаг.** Этап 2: товары и склады с миграцией EF Core, валидацией, поиском и интеграционными проверками на PostgreSQL.
