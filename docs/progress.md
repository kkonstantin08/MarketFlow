# Состояние проекта

## 2026-11-13 — Этап 1: основа API

**Готово.** Созданы `MarketFlow.sln`, API на .NET 10, xUnit-проект с тестовым хостом и `compose.test.yaml` с PostgreSQL 17. API отвечает `GET /health`, Swagger UI и OpenAPI доступны в Development. SDK 10.0.404 установлен в `~/.dotnet` через официальный скрипт, системная установка не менялась.

**Проверки.** Увиден RED: без маршрутов три smoke-проверки падали (`/health`, Swagger и подключение к отсутствующей тестовой БД). После исправления `docker compose -f compose.test.yaml up -d --wait`, `dotnet test MarketFlow.sln --no-restore` прошёл (3 проверки), `dotnet build MarketFlow.sln --no-restore` прошёл без предупреждений, `dotnet list MarketFlow.sln package --vulnerable --include-transitive` не нашёл уязвимых пакетов. Реальный API на `127.0.0.1:8080` также ответил на `/health`, Swagger UI и JSON спецификации. Docker Compose и PostgreSQL 17. Разработка проверялась только на macOS arm64.

**Изменения.** README содержит команды запуска API и тестовой БД. OpenAPI.NET закреплён на исправленной версии 2.7.5 из-за известной уязвимости в 2.3.0. Superpowers-инструкции в доступном каталоге навыков этой сессии не обнаружены; TDD выполнен по `docs/testing.md`.

**Следующий шаг.** Этап 2: товары и склады с миграцией EF Core, валидацией, поиском и интеграционными проверками на PostgreSQL.

## 2026-11-09 — BOOTSTRAP

**Текущий этап.** BOOTSTRAP завершён. Владелец согласовал складской контракт и формат интерфейса. Реализация ожидает `GO`.

**Что завершено.** Созданы правила работы, навигация по документации, продуктовые границы, предметная модель, контракт API, архитектура, этапы реализации, стратегия проверок и исследование интерфейса. Рабочий каталог исходно был пустым. [План](plan.md) остаётся списком предстоящих этапов.

**Проверки среды.** Обе записи плагинов включены в локальной конфигурации Codex, файлы инструкций присутствуют. Прочитаны Superpowers `using-superpowers`, `brainstorming`, `writing-plans`, `test-driven-development`, `systematic-debugging`, `verification-before-completion`, `executing-plans` и Ponytail `ponytail`. Для BOOTSTRAP использованы разбор требований, предварительный план, сверка спецификации и минимизация объёма. TDD и систематическая отладка применяются при реализации. Настройки среды оставлены как были.

**Проверки документов.** Проверены 13 ожидаемых файлов, 40 внутренних Markdown-ссылок, наличие входных данных, ошибок и приёмки во всех пяти разделах MVP, соответствие этих разделов плану и стратегии тестов, маршруты примеров README и правила `.gitignore`. Выполнен `git diff --cached --check`. Сборка, тесты и запуск API не выполнялись, так как приложение ещё не создано.

Публичные материалы Ozon открылись в веб-инструменте, а рабочий кабинет недоступен для проверки. Источники и границы наблюдений записаны в [исследовании](design/research.md).

В интерфейс входят Swagger UI и одна демонстрационная страница в направлении C на HTML/CSS/JS. Сценарий и критерии записаны в [спецификации](specs/mvp.md#демонстрационная-страница).
