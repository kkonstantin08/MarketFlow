# Журнал решений

При изменении принятого решения добавляй датированную запись со ссылкой на заменяемую и обновляй затронутые документы.

| Дата | Проблема | Решение | Причина | Альтернативы |
| --- | --- | --- | --- | --- |
| 2026-11-09 | Где разместить API, логику и хранение? | Один API на .NET 10, один PostgreSQL, один проект xUnit. EF Core с Npgsql для обычного доступа к данным. | Мало компонентов и одна граница транзакции. | Раздельные проекты слоёв добавят связность и настройку. Микросервисы усложнят запись и запуск. |
| 2026-11-09 | Как защитить остатки от гонок и частичной записи? | Хранить одну строку на пару. Использовать условное атомарное обновление и прибавление через upsert. Записывать факт, остаток и журнал одной транзакцией. | База решает конфликты и обеспечивает атомарность между экземплярами API. | Блокировка строки с чтением требует дополнительных шагов. Serializable требует обработки повторов. Пересчёт всего журнала усложнит запрос остатков. |
| 2026-11-09 | Как распознать повтор приёмки? | Согласовано. Уникальный нормализованный номер поставки. Один номер на товар и склад. Точный повтор возвращает исходный факт, изменённый запрос получает конфликт. | Проверка уникальности работает и при параллельной записи. Одной позиции хватает для базового сценария. | Заголовок с отдельным ключом требует дополнительного протокола. Документ из нескольких позиций требует модели строк и правил их атомарной записи. |
| 2026-11-09 | Как трактовать резерв? | Согласовано. Резерв увеличивает зарезервированное количество и остаётся активным. В MVP нет снятия, срока действия и отгрузки. | Достаточно для проверки доступности без моделирования заказа и жизненного цикла. | Добавить отмену и TTL после подтверждения отдельного сценария. |
| 2026-11-09 | Как проверять запуск и поведение БД? | xUnit и тестовый PostgreSQL, Compose для локального запуска, GitHub Actions на Linux. | Тесты используют те же ограничения и блокировки, что приложение. | InMemory годится для простых проверок, но не воспроизводит конкурентные записи PostgreSQL. |
| 2026-11-09 | Какой интерфейс входит в MVP? | Согласовано. Swagger UI и одна демонстрационная страница в направлении C на HTML/CSS/JS. Страница обслуживается тем же ASP.NET Core. | Одной страницы хватает для показа складского сценария. Swagger UI даёт доступ ко всему контракту API. | Рабочий кабинет на Razor Pages или статический REST-клиент с отдельными экранами. [Сравнение вариантов](design/research.md). |
| 2026-11-13 | Как создать тестовые данные для демонстрации? | На странице можно выбрать или создать товар и склад. | Не нужно переключаться в Swagger и вручную переносить идентификаторы для основного сценария. | Создание только через Swagger требует ручной передачи ID. |
